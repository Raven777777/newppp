## 使用约定

1. **归属**：新任务必须落在「连通 / 生命周期 / 可维护」三者之一，否则进 Backlog。
2. **触发条件**：Backlog 条目必须写清"观察到什么现象才启动"，没有触发条件的需求直接拒绝（防止 QUIC 指纹混淆这类项悄悄插队）。
3. **验收即完成**：每项的完成标准是一条能跑的命令或一个具名测试，不写形容词。
4. **顺序**：P0 → P1 → P2 → P3，P4 穿插做；Backlog 不占带宽，只有触发条件命中才启动。

### P3 生命周期与运维（约 1 周）

> 实现依据：P1 #11（`lifecycle_no_leak_ports_reusable`）已在 Linux CI 上证实——`run_wt` accept 循环被 abort 时，其内部 `tokio::spawn` 的**每连接任务**仍持有 `Connection` 克隆继续运行，QUIC endpoint driver（及其绑定的 UDP socket）迟迟不释放（实测 ≥5s 仍 `AddrInUse`）；而测试 harness 里"先 `conn.cancel.cancel()` → 等 300ms drain → 再 abort 监听任务"的时序可让端口立即释放（见 [tests/e2e.rs](../tests/e2e.rs) 的 `TestServer::shutdown`，即 P3-1 停机序列的原型）。生产路径 `server::run` 目前只有 `tasks.abort_all()`，存在同类残留，P3-1 必须沿用上述时序。

- [x] **P3-1 优雅停机**：SIGTERM/SIGINT → 停止接受新连接（关监听/拒绝新会话）→ 主动 cancel 全部活跃连接（`ServerState.conns` 的父 token，发送 CONNECTION_CLOSE 并快速 drain）→ 排空在途会话（默认 10s，`--shutdown-grace` 可调；超时强杀）→ drop 监听句柄 → 退出码 0。
  - 做法：`run_with_shutdown(cfg, token)`（[server/mod.rs](../src/server/mod.rs)）复刻 `TestServer::shutdown` 三段时序：cancel 活跃连接父 token（其 watcher 显式关 QUIC 传输，子 token 级联取消会话泵）→ 轮询 `active_sessions` 排空（默认 10s，超时 WARN 强杀）→ `tasks.abort_all()` drop 监听句柄；`run` 改为 ctrl_c → `CancellationToken`；reaper 挂同一 token。退出路径保持 `Ok(())`（退出码 0）。
  - 验收：e2e `graceful_shutdown_releases_ports`（先建立一条真实 WT 连接再 cancel token，断言 10s 内退出且 WT/fallback 端口立即可 rebind）。
  - 债：D4
- [x] **P3-2 `--health <127.0.0.1:port>`**：`/healthz` 返回 JSON `{uptime, active_sessions, wt_conns, transport: "wt|fallback|mixed", circuit: "closed|open", last_fallback_at}`，客户端/服务端共用（[src/health.rs](../src/health.rs)）。`last_fallback_at` 由客户端 Outbound 降级路径写入全局原子（毫秒级时间戳，从未用过为 null）。

## 明确的"不做"（写下来防止以后摇摆）

- **不加 Alt-Svc**：UDP 443 现在不应答网页请求，广播 Alt-Svc 等于邀请浏览器来探测一个答不上话的端口。即使将来做了 h3 共宿也不加——暴露面只增不减。
- **不做多级 fallback**：WT→POST/WS 已覆盖全部三种部署形态，POST 再挂时节点大概率整个不可达。
- **不做 per-user ACL/配额/计费**：`--auth` 多用户 + 连接级限速对"少量可信用户"够用。
- **不做自适应调参**（recv-window/conns 自动调优）：替代动作是把调参经验写进 [运维手册.md](运维手册.md)（见 P4-2/P4-3）。
- **不拆 crate/微服务**：目录边界已清楚，`lib.rs` 已支撑集成测试。
